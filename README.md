# NIS Academy — интерактивный фронтенд-прототип

Кликабельный прототип платформы онлайн-репетиторства (групповые занятия) по ТЗ `docs/PRD.md`.
**Без бэкенда:** все данные — локальные моки в `localStorage`; оплата, уведомления и Zoom — демонстрационные.

## Запуск

```bash
npm install && npm run dev
```

Откройте http://localhost:5173 → «Демо-вход» → выберите роль и профиль.
Сборка: `npm run build` (проверка типов + production-бандл в `dist/`).

## Стек

React 19 + TypeScript + Vite, Tailwind CSS v4, React Router, компоненты в стиле shadcn/ui на Radix UI, иконки Lucide, toast — Sonner.

## Структура

```
src/
├── types.ts               # клиентские типы (User, Order, Lesson, QuotaTransaction, …)
├── mocks/seed.ts          # seed-данные (даты относительно первого запуска)
├── services/
│   ├── mockApi.ts         # бизнес-операции: оплата, резерв, отчёт, подтверждение, перераспределение…
│   ├── selectors.ts       # вычисляемые остатки квот и выборки
│   └── store.tsx          # стор + localStorage (версия схемы), useAction с loading/toast
├── components/            # ui/ примитивы, common, domain (карточки, календарь), shell (шапка, роли)
├── layouts/               # PublicLayout, DashboardLayout (сайдбар/мобильное меню, проверка роли)
├── pages/                 # public, parent, student, teacher, moderator, admin
└── styles/index.css       # семантические токены
docs/  PRD.md · design.md · pages.md
```

Чтобы подключить реальный API, достаточно заменить функции `services/mockApi.ts` — экраны вызывают их через `useAction(op)`.

## Модель квот

Остатки не хранятся счётчиком — они вычисляются из журнала `QuotaTransaction` на уровне **ученик + заказ + предмет**:
`grant` (оплата), `reserve` (урок опубликован), `release` (отмена / пропуск по демо-правилу), `consume` (подтверждение отчёта), `reallocate_in/out`, `expire`.
Свободно = куплено − резерв − списано − истекло. Трассировка «заказ → квота → участие → урок» — в Аналитике (клик по заказу).

## Демо-сценарии

| Сценарий | Как пройти |
|---|---|
| P-01 Покупка | Гость → Пакеты → Купить → (в пакете «4 предмета на выбор» — выбрать ровно 4 предмета, уроки делятся поровну) → распределить ровно N → данные семьи → оферта → «Отклонено» (квот нет) → «Повторить оплату» → «Успешно» → «Повторный демо-webhook» (квоты не удваиваются) |
| P-02 Проверка учителя | Модератор → Преподаватели → «Назначить роль учителя» Сабине Алиевой → демо-вход учителем Сабиной → анкета → отправить → модератор одобряет/возвращает. В очереди уже есть Олжас Нуриев |
| P-03 Планирование | Модератор → Календарь → «Создать урок». Завтра 16:00 — конфликт; у Даны нет квоты; у Армана заказ не оплачен; группа «Математика 6 (рус) — А» — лимит 2 |
| P-04 Отчёт | Учитель Ирина Петрова → «Отчёты» → урок «Ждёт отчёта» → посещаемость и заметки → модератор → Отчёты → подтвердить / вернуть. Повторное подтверждение ничего не списывает |
| Отзывы | Ученик Тимур → «Оцени урок» → звёзды и комментарий учителю (доступно сразу после окончания урока, кроме отменённых и пропусков). Заметки учителя видит только родитель (Обратная связь) |
| P-05 Перераспределение | Родитель Асель Нурланова → Пакеты и квоты → ЗК-1002 → «Перераспределить». Обмен стандарт ↔ премиум (информатика) запрещён — демо-допущение |
| P-06 Продление | Родитель → «Продлить» → новый отдельный заказ; общий остаток и детализация по заказам — на странице «Пакеты и квоты» |

Правило пропусков («вернуть резерв» / «списать») переключается в Админ-демо → «Демо-настройки». Ни одно демо-правило не является утверждённой политикой (раздел 13 ТЗ).

**Сброс:** кнопка «Сбросить демо-данные» в сайдбаре кабинета, на `/demo` и в админке.
